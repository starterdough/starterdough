Accounts, end to end.

- **Email flows.** Sign-up with email verification, password reset, change email confirmed from
  the old address, and account deletion confirmed by email. Emails print to the API console in
  development and go through Resend when a key is set.
- **Social sign-in.** GitHub and Google switch on when their credentials are present. The sign-in
  page asks the API which providers are live instead of keeping a second configuration.
- **Two-factor and passkeys.** TOTP with backup codes, and WebAuthn passkeys, managed from the
  security settings. Sessions can be listed and revoked.
- **Rate limits.** Better Auth’s own per-IP limits on the auth routes, plus a limiter on every
  procedure.
- **Session guard.** One universal `load` protects the app routes in server rendering *and* in the
  static SPA, so the same code redirects to sign-in on every target.
